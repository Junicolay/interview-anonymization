# Data management

This directory contains dataset metadata and experiment artifacts used by
the interview-anonymization research project.

Large datasets, raw audio files, model weights and local caches should remain
outside Git unless there is a specific reason to version them.

## Expected data

### VoxCeleb audio

The speaker-verification pipeline expects VoxCeleb audio files under:

`voxceleb1/wav/`

The dataset is not distributed with this repository. Obtain and store it
locally in accordance with the dataset's access and usage conditions.

### Utterance metadata

Default path:

`data/metadata/voxceleb_utterances.parquet`

The metadata must contain the following columns:

- `speaker_id`: speaker identifier.
- `video_id`: source video identifier.
- `path`: path to the corresponding audio file.

The metadata file is an input to the speaker-verification pipeline and is
not generated by the pipeline itself.

## Experiment artifacts

### Verification trials

`data/trials/` contains speaker-verification trial files.

The script `scripts/run_speaker_verification.py` generates trials from the
metadata using a configurable random seed. Its default output is:

`data/trials/voxceleb_verification_trials_legacy_reproduction.csv`

The existing `voxceleb_verification_trials.csv` is a separate artifact.
Do not overwrite or replace existing trial files without first checking
their provenance and whether they are needed to reproduce earlier results.

### Embedding cache

The default local cache is:

`data/cache/ecapa_embeddings.sqlite`

It stores extracted speaker embeddings so they can be reused across runs.
This cache is generated locally and should not normally be committed.

### Reports

The verification script writes experiment reports under:

`reports/speaker_verification/`

These reports include scored trials and a JSON report with configuration,
input hashes, metrics and runtime. Reports should be retained when needed
to document or reproduce an experiment, but large generated files should
not be committed indiscriminately.

## Reproducibility and version control

Before running an experiment, check its input and output paths to avoid
overwriting existing artifacts.

For reproducibility, retain the relevant dataset version, metadata,
trial-generation parameters, random seed, model identifier and Git commit.

Do not use `git add .` to version data. Inspect `git status` and stage only
the specific files that are intentionally part of a commit.

This directory documents expected inputs and outputs; it does not imply that
all listed datasets or artifacts are present in the repository.
